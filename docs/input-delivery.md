# Input delivery and predicted lane state

`GestureRecognizer.recognize` proposes a sequence and leaves the predicted game lane unchanged. Until that sequence is acknowledged, further frames cannot create another sequence. `KeyboardBridge.send_action` validates all actions before injection and returns an immutable `DeliveryResult` with the requested sequence, the completed prefix, an error reason, and an uncertainty flag. An action completes only when key down, the hold, and key up finish successfully.

`acknowledge_delivery` applies only that completed prefix to the predicted lane and action timers. If a left-to-right transition requests two Right strokes and only the first completes, the predicted lane moves from LEFT to CENTER. The second stroke may have partly reached Windows or the game; the controller pauses instead of claiming RIGHT or silently rolling back to LEFT. No automatic retry follows. A mismatched acknowledgement also pauses input.

Any unsuccessful dispatch requires deliberate recovery. The player must inspect and center the actual game, focus the preview, and press R. Possibly held keys are released first; a failed release prevents reset. The player must then return to the physical neutral zone before a new gesture can trigger. Calibration and missing tracking preserve the input-failure state. The application also attempts pending key releases during shutdown, including after an interrupt or runtime exception.

The bridge reports Windows insertion facts, not game acceptance. Games may ignore or combine correctly inserted input, and the current predicted lane is not read back from the game. Actual acceptance and focus policies require separate live validation. Replay explicitly simulates successful delivery and records that condition; it never sends native keyboard input.

Tests exercise actual PyDirectInput event construction with native `SendInput` replaced: successful sequences, failed down/up, partial NumLock event insertion, a failed second stroke, runtime errors and interrupts, release retries and application shutdown. Main-loop tests run the real recognizer and bridge against those controlled native outcomes. The recorded Weizmann fixture checks that the new acknowledgement protocol preserves the two reviewed jump events and the short negative standing segment. These checks do not establish physical input latency or game accuracy.
