# Arming, focus and global controls

Input starts disarmed, including when a caller constructs `KeyboardBridge` without an explicit permission callback. After a successful standing calibration, the player focuses the intended game and presses F8. The foreground window is captured at that hotkey event and must still match when the request is processed. Arming waits up to one second for a reliable upright pose captured after the request, received within the last 250 ms and in a physical lane matching the controller's expected game lane. It cannot clear a delivery fault or unresolved pending sequence. The accepted arm observation emits no action, while the next new gesture remains eligible.

F7 begins calibration, F8 requests arming, F9 pauses, and F10 requests exit. Global hotkeys are registered with `MOD_NOREPEAT` and owned by a dedicated Windows message-loop thread, so pause revokes permission without waiting for camera inference or the OpenCV key loop. Registration failure stops startup, and partial registration is cleaned up. The owner thread unregisters all hotkeys during shutdown. [Microsoft's RegisterHotKey documentation](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey) describes thread-owned messages and the repeat-suppression flag.

The session checks foreground ownership on its monitor loop and every delivery permission request. Identity includes the full-width window handle, owning process and thread, and title. Loss of focus, a changed identity/title, unavailable global controls, missing pose tracking, calibration, adjustments, lane reset, or a delivery failure disarms input. Returning focus does not rearm it. Generation checks prevent a queued arm request from overriding a later pause. The bridge checks permission for each stroke and again immediately before key down. A pause during a key hold still releases the key and marks that stroke uncertain; a stopped second stroke cannot send another down event.

Resume while upright in the physical lane matching the game's expected lane, then focus the game and press F8. If a native delivery fault occurred, first inspect and center the actual game, focus the preview and press R. Pending releases must succeed before reset; F8 is still required afterward. This avoids a return-to-center pulse when resuming from an outer lane.

This is window-level protection, not a game integration. Windows `SendInput` does not atomically bind an event to a selected game, so a focus switch between the final check and insertion remains a narrow race. Identical-title tabs or a focused address field inside the same browser window cannot be distinguished by this guard. Actual game acceptance, physical hotkey presses, OS scheduling latency, and player identity are not established by the current tests. Capture and pose inference have separate processes and bounded parent polling. The input guard uses the returned pose's source receipt age, so new camera frames cannot conceal stale inference. [Pose-worker details](pose-worker.md) document initialization/inference deadlines and forced-shutdown limits.

The tests cover delayed arm requests, stale/crouched poses, lane matching, process/thread/title changes, focus loss between two strokes, pause during a hold, native registration failures, registration-thread ownership and cleanup, default-disarmed main behavior, and background pause while the frame loop is idle. Native `SendInput` is mocked. Recorded Weizmann observations remain quiet while disarmed and retain the two reviewed jumps after explicit arming. This is a limited regression, not broad gesture accuracy.

Run `python -m evaluation.check_global_controls` for the actual Windows registration check. It keeps input disarmed, posts a synthetic pause message only to its own worker, stops the worker, and re-registers the keys to verify cleanup. It opens no webcam and injects no keyboard input; a synthetic message is not evidence that a physical F9 press was tested. The local 64-bit Windows check passed; the recorded result is in `docs/benchmarks/global-controls-windows.json`.
